## MODIFIED Requirements

### Requirement: 授权和撤销必须是显式、最小且会话隔离的

SSH 面板 SHALL 只展示非敏感 Host 摘要，让用户显式选择一个或多个 alias 后授权到当前会话。授权与撤销 SHALL 对称地遵循"草稿 + 显式提交"：新增与移除都先在弹层内形成草稿，只有用户点击对应的提交动作后才向 Host 发起变更请求，任何单次点击都 MUST NOT 直接改变当前会话的授权集合。授权只对当前 live Agent/Session 生效，不自动继承到其他会话；撤销提交 SHALL 立即阻止新的 SSH 工具调用，并使当前主体的工具可见性与授权状态收敛为空或剩余集合。

#### Scenario: 授权一个 alias
- **WHEN** 用户在当前会话面板选择 alias `alpha` 并确认授权
- **THEN** 只有该当前 Agent/Session 获得 `alpha`，其余 Agent/Session 仍看不到 SSH 工具或 `alpha` 的信息

#### Scenario: 撤销授权
- **WHEN** 用户把当前会话已授权的 alias `alpha` 标记为待撤销并提交撤销
- **THEN** 提交前不发起任何撤销请求；提交后 Host 立即阻断以该 Agent/Session 执行的后续 SSH 工具调用，工具 Schema/工具变更通知移除相应能力，其他会话不受影响

#### Scenario: 点击已授权行不改变授权
- **WHEN** 用户单击一个已在当前会话获得授权的行
- **THEN** 该 alias 只进入待撤销草稿并显示为待撤销，授权集合、工具可见性与按钮文案之外的状态保持不变，直到用户显式提交撤销

#### Scenario: 关闭弹层丢弃未提交的撤销
- **WHEN** 用户标记了一个或多个待撤销 alias 后按 Esc、点击外部或点击关闭按钮
- **THEN** 未提交的撤销草稿被丢弃，已确认授权保持不变，且不产生任何 RPC

#### Scenario: 重复授权和并发授权
- **WHEN** 同一主体重复授权同一 alias，或对同一主体并发提交互不冲突/冲突的授权变更
- **THEN** 操作具备幂等或确定性合并语义，不产生重复工具、越权集合或丢失已确认的独立授权

### Requirement: 会话输入栏必须提供 SSH 连接多选选择器

会话输入栏 SHALL 新增独立「SSH 连接」按钮，参考数据库连接选择器的按钮和向上弹层交互，并与已有数据库/API 按钮并存而不替换它们。弹层 SHALL 显示「选择 SSH 连接」、已授权与待授权数量、可搜索的 Host 摘要列表、选中态标记和「管理 SSH 连接」入口；搜索 SHALL 仅使用 alias、host、user、环境或标签等已允许的人类管理摘要字段。列表 MUST NOT 展示密码、私钥内容、密钥口令、Token、完整 ProxyCommand 或配置文件原文。

弹层表面 MUST 完全不透明：无论宿主把菜单材质令牌定义为实心还是带 alpha 的材质，弹层背景、列表区域与页脚都不得让下层页面或对话内容透出。选择行 SHALL 使用菜单式选中语言而不是逐行复选框：未选择的行不带状态标记，待授权草稿行与已授权行分别用不同的状态标记与底色区分，且未选择的行 MUST NOT 显示「待授权」字样。

按钮 SHALL 在无授权时显示「SSH 连接」，单 Host 授权时显示可截断的 alias，多 Host 授权时显示「SSH · N」；完整已授权摘要通过 tooltip/可访问名称提供。加载、待提交、失败、无 Host、无搜索结果和无可信当前会话绑定 SHALL 有明确状态，不能将授权标记等同于 SSH 连接成功。即使 Host 库仅有一个 Host，系统 MUST NOT 自动选择或自动授权。

#### Scenario: 无授权时打开选择器
- **WHEN** 用户在没有 SSH 授权的当前会话点击「SSH 连接」
- **THEN** 弹层列出允许向人类管理 UI 展示的非敏感 Host 摘要，所有条目默认未选中且不带状态标记；打开、搜索或关闭弹层不向 Agent 授权、不注册 SSH 工具，也不自动连接远端

#### Scenario: 弹层表面不透字
- **WHEN** 弹层在浅色或深色主题下打开，且其下方存在对话正文、输入栏或其他浮层内容
- **THEN** 弹层覆盖区域内的下层文字与控件不可见，弹层表面为完全不透明背景

#### Scenario: 勾选多个 Host 后显式授权
- **WHEN** 用户选中 alias `alpha` 和 `beta` 两行（点击行或键盘 Enter/Space，列表不再使用复选框），再点击「授权到当前会话」
- **THEN** 选中阶段只显示待授权草稿与「待授权」标记；经 Host 端确认精确主体和授权事务后才显示两项「已授权」与「SSH · 2」，并只为当前 live Agent 披露对应工具

#### Scenario: 单连接也不自动授权
- **WHEN** Host 库只有一个 Host，或用户首次打开选择器
- **THEN** 该 Host 不自动获权；用户仍须选中并显式提交当前会话授权

#### Scenario: 管理入口打开 Host 管理面
- **WHEN** 用户点击弹层里的「管理 SSH 连接」，或空态里的同名入口
- **THEN** 弹层关闭并切到本插件的 SSH 面板 Hosts 页；该跳转不改变当前会话的授权集合，也不发起授权或撤销请求

#### Scenario: 取消勾选和撤销全部
- **WHEN** 用户点击一个已授权行把它标记为待撤销并提交「撤销所选」，或点击「撤销全部授权」
- **THEN** 点击行本身不发起撤销；「撤销所选」只提交被标记的别名，「撤销全部授权」提交全部已授权别名；Host 收到并提交撤销后立即阻断新工具调用，按钮、弹层和 SSH 面板按 Host 确认状态同步，撤销全部不改 Host 库

#### Scenario: 搜索不破坏已有选择
- **WHEN** 用户在弹层搜索 alias、host、user、环境或标签，随后清空搜索
- **THEN** 过滤仅改变列表展示，不自动增减授权、待授权草稿或待撤销草稿；搜索无结果给出明确空态，已有授权保持不变

#### Scenario: 键盘操作与弹层关闭
- **WHEN** 用户通过键盘打开选择器、移动焦点并切换行的选中状态，随后按 Esc、点击外部或点击关闭按钮
- **THEN** 控件具有可访问名称及可读选中状态，支持 Tab/方向键和 Enter/Space 操作；关闭返回合理焦点且不提交未确认的新增或撤销草稿
